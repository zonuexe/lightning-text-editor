# 40分エディタのアーキテクチャ設計

ターミナルエディタの基本構造は、実は**ゲームループ**と非常によく似ています。  
「状態を持ち、キー入力を受け取り、状態を更新し、画面を描画する」というループを回すだけです。

---

## 🏗 全体像（MVC / ゲームループモデル）

```text
 ┌────────────────────────────────────────────────────────┐
 │                    EditorState                         │
 │  - lines: string[]      (テキストバッファ)               │
 │  - cursorX, cursorY: int (画面/テキスト内のカーソル位置)  │
 │  - filename: string     (保存先ファイル名)              │
 │  - isRunning: bool      (ループ継続フラグ)              │
 └───────────────────────┬────────────────────────────────┘
                         │
        ┌────────────────┼────────────────┐
        │                                 │
        ▼                                 ▼
┌───────────────────┐             ┌───────────────────┐
│   Input Handler   │             │     Renderer      │
│ (キー入力を解釈)    │             │ (画面クリア＆描画) │
│ - 矢印/hjkl: 移動 │             │ - テキスト描画    │
│ - 文字: 挿入      │             │ - ステータスバー  │
│ - BS: 削除        │             │ - カーソル移動    │
│ - Ctrl+S: 保存    │             │                   │
│ - Ctrl+Q: 終了    │             └───────────────────┘
└───────────────────┘
```

---

## 🔄 コア・イベントループ

すべての言語で共通するメインループの骨格です。

```text
1. ターミナルを Raw Mode（生モード）に変更
2. 画面を初期化（画面クリア）
3. ループ開始:
   a. render(): 現在のバッファとカーソルをターミナルに描画
   b. key = read_key(): キーを1文字（またはエスケープシーケンス）読み込む
   c. handle_key(key):
      - 終了キーなら isRunning = false
      - 保存キーなら save_file()
      - 移動キーなら cursorX / cursorY を更新
      - 文字キーなら lines に文字を挿入
      - Backspaceなら lines から文字を削除
4. ループ終了後:
   - ターミナルを通常モード（Cooked Mode）に復元
   - 画面をクリアして終了メッセージを表示
```

## 📦 最小限の状態（EditorState）

40分で実装するMVPでは、複雑なデータ構造（Gap BufferやPiece Table）は使わず、**「文字列の配列（`lines = [""]`）」**だけで十分です。

```typescript
// 状態の例（TypeScript）
interface EditorState {
  lines: string[];      // 各行のテキスト。初期値は [""]
  cursorX: number;     // カラム位置（0始まり）
  cursorY: number;     // 行位置（0始まり）
  filename?: string;   // 保存先ファイルパス
  isModified: boolean; // 変更フラグ（ステータスバー表示用）
  mode?: string;       // Vim風にする場合: 'NORMAL' | 'INSERT'
}
```

## 🎨 描画パイプライン（Renderer）

画面の再描画は、毎フレーム以下のステップで文字列を結合してターミナルに出力します。

1. **`\x1b[?25l`**: カーソルを非表示にする（チラつき防止）
2. **`\x1b[H`**: カーソルを画面左上（1行1列）に戻す
3. **バッファの描画**: 各行を出力し、行末で `\x1b[K`（行末までクリア）を呼ぶ
4. **ステータスバーの描画**: 背景色付き（反転表示 `\x1b[7m`）でファイル名や操作ヘルプを表示
5. **カーソル位置の復帰**: `\x1b[${cursorY + 1};${cursorX + 1}H` でカーソルを本来の位置へ
6. **`\x1b[?25h`**: カーソルを再表示する

## 🎮 入力ハンドリングのツボ

### 1. 制御文字（Ctrlキー）
ターミナルでは、`Ctrl + [A-Z]` は ASCIIコード `1〜26` として送られてきます。
- `Ctrl+A`: `\x01`
- `Ctrl+C`: `\x03`
- `Ctrl+Q`: `\x11`
- `Ctrl+S`: `\x13`

### 2. 特殊キー（矢印キー）
矢印キーは1文字ではなく、3バイトのエスケープシーケンスとして届きます。
- 上: `\x1b[A`
- 下: `\x1b[B`
- 右: `\x1b[C`
- 左: `\x1b[D`

## 🧩 進入路ごとの組み立て順

| 進入路 | 第1ステップ | 第2ステップ | 第3ステップ | 第4ステップ |
| :--- | :--- | :--- | :--- | :--- |
| **🎨 見た目から** | 画面クリア & ステータスバー描画 | サンプル行の描画 & カーソル配置 | Raw Mode & キー取得 | 入力・編集ロジック接続 |
| **🎮 入力から** | Raw Mode & キーエコー | 終了キー & 矢印キー判定 | カーソル移動 & 画面再描画 | バッファ操作 & ファイル保存 |
| **📄 ロジックから** | `lines` への文字挿入・削除関数 | 行分割・改行処理 | Raw Mode & キー受け渡し | 画面描画との合流 |
