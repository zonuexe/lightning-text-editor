# 40分エディタのアーキテクチャ設計

ターミナルエディタの基本構造は、実は**ゲームループ**と非常によく似ています。  
「状態を持ち、キー入力を受け取り、状態を更新し、画面を描画する」というループを回すだけです。

---

## 🏗 全体像（MVC / ゲームループモデル）

```text
 ┌────────────────────────────────────────────────────────┐
 │                    EditorState                         │
 │  - lines: string[]      (テキストバッファ)               │
 │  - cursorX, cursorY: int (画面/テキスト内のカーソル位置)  │
 │  - filename: string     (保存先ファイル名)              │
 │  - isRunning: bool      (ループ継続フラグ)              │
 └───────────────────────┬────────────────────────────────┘
                         │
        ┌────────────────┼────────────────┐
        │                                 │
        ▼                                 ▼
┌───────────────────┐             ┌───────────────────┐
│   Input Handler   │             │     Renderer      │
│ (キー入力を解釈)    │             │ (画面クリア＆描画) │
│ - 矢印/hjkl: 移動 │             │ - テキスト描画    │
│ - 文字: 挿入      │             │ - ステータスバー  │
│ - BS: 削除        │             │ - カーソル移動    │
│ - Ctrl+S: 保存    │             │                   │
│ - Ctrl+Q: 終了    │             └───────────────────┘
└───────────────────┘
```

---

## 🔄 コア・イベントループ

すべての言語で共通するメインループの骨格です。

```text
1. TTY チェック後、元の端末設定を保存し Raw Mode（生モード）に変更
2. 代替画面バッファ（\x1b[?1049h）や Bracketed Paste（\x1b[?2004h）を有効化
3. 画面を初期化（画面クリア）
4. ループ開始:
   a. resize 要求があれば端末サイズを再取得し、カーソル/スクロール位置をクランプ
   b. render(): 現在のバッファ（制御文字・タブ展開済み）とカーソルを同期描画
   c. key = read_key(): タイムアウト付きでキー（またはエスケープシーケンス）を読み込む
   d. handle_key(key):
      - 終了キーなら isRunning = false
      - 保存キーなら save_file()
      - 移動キーなら cursorX / cursorY を更新
      - 文字キーなら lines に文字を挿入
      - Backspaceなら lines から文字を削除
5. ループ終了後（必ず「制御シーケンスを flush してから」端末設定を復元）:
   - 拡張モード解除（\x1b[?2004l 等）と代替画面バッファ復帰（\x1b[?1049l）
   - カーソルを表示状態（\x1b[?25h）＆装飾リセット（\x1b[0m）に戻し flush
   - ターミナルを元のモード（Cooked Mode）に復元
```

## 📦 最小限の状態（EditorState）

40分で実装するMVPでは、複雑なデータ構造（Gap BufferやPiece Table）は使わず、**「文字列の配列（`lines = [""]`）」**だけで十分です。

```typescript
// 状態の例（TypeScript）
interface EditorState {
  lines: string[];      // 各行のテキスト。初期値は [""]
  cursorX: number;     // カラム位置（0始まり）
  cursorY: number;     // 行位置（0始まり）
  filename?: string;   // 保存先ファイルパス
  isModified: boolean; // 変更フラグ（ステータスバー表示用）
  mode?: string;       // Vim風にする場合: 'NORMAL' | 'INSERT'
}
```

## 🎨 描画パイプライン（Renderer）

画面の再描画は、毎フレーム以下のステップで文字列を結合してターミナルに出力します。

1. **`\x1b[?2026h` + `\x1b[?25l`**: 同期描画を開始し、カーソルを非表示にする（チラつき防止）
2. **`\x1b[H`**: カーソルを画面左上（1行1列）に戻す
3. **バッファの描画**: 各行の制御文字（`\x1b` 等）可視化・タブ展開・画面幅クリップを行った上で出力し、行末で `\x1b[K` を呼ぶ
4. **ステータスバーの描画**: 背景色付き（反転表示 `\x1b[7m`）でファイル名や操作ヘルプを表示（右端自動折り返しや最下行スクロールを防ぐため `cols - 1` 以内に収める）
5. **カーソル位置の復帰**: `\x1b[${cursorY + 1};${cursorX + 1}H` でカーソルを本来の位置へ
6. **`\x1b[?25h` + `\x1b[?2026l`**: カーソルを再表示し、同期描画を終了して一括出力する

## 🎮 入力ハンドリングのツボ

### 1. 制御文字（Ctrlキー）
ターミナルでは、`Ctrl + [A-Z]` は ASCIIコード `1〜26` として送られてきます（`Enter` と `Ctrl+M`、`Tab` と `Ctrl+I` を区別したい発展実装では Kitty keyboard protocol / `modifyOtherKeys` が使われます）。
- `Ctrl+A`: `\x01`
- `Ctrl+C`: `\x03`
- `Ctrl+Q`: `\x11`
- `Ctrl+S`: `\x13`

### 2. 特殊キー（矢印キー）と単独 `Esc` の曖昧性
矢印キーなどは `\x1b` から始まる複数バイトのエスケープシーケンスとして届きます。
- CSI シーケンス: `\x1b[A` / `B` / `C` / `D`（パラメータ付きは `\x1b[1;2A` 等、終端バイトは `0x40〜0x7E`）
- SS3 シーケンス: `\x1bOA` / `B` / `C` / `D`、`\x1bOH` / `F`（Application Cursor Mode 等の端末で送られる）

**実装上の 3 つの落とし穴**:
1. **単独 `Esc` キーでハングさせない**: `\x1b` を読んだ直後に無条件で次の `read(1)` をブロックすると、ユーザーが単独の `Esc` を押したときに次のキーまで固まります。`select` 等で **20〜50ms の短タイムアウト** 待ちをし、後続が来なければ単独 `Esc` として確定します。
2. **チャンク境界（分断・結合）に備える**: SSH 越しや高速連打では `\x1b` と `[A` が別々の `read` に分かれたり、`\x1b[A\x1b[B` が 1 チャンクにまとまって届いたりします。3 バイト固定長比較ではなく、状態を持つストリームデコーダで切り出します。
3. **未知の CSI シーケンスを文字挿入しない**: 未対応の修飾キーやマウス応答・フォーカスイベント（`\x1b[I` / `\x1b[O`）が来ても、CSI の終端バイト（`0x40〜0x7E`）まで読み飛ばして破棄しないと、`1;2A` 等の残骸がバッファに挿入されてしまいます。

### 3. ウィンドウリサイズ（`SIGWINCH`）
端末ウィンドウのサイズが変わると `SIGWINCH` シグナルが届きます。シグナルハンドラ内で直接描画すると競合や画面崩れを起こしやすいため、**ハンドラでは `needsResize = true` のフラグだけを立て、`read` の `EINTR`（システムコール中断）を再試行しつつ、イベントループ先頭で端末サイズを再取得して再描画する**のが定石です。

## 🧩 進入路ごとの組み立て順

| 進入路 | 第1ステップ | 第2ステップ | 第3ステップ | 第4ステップ |
| :--- | :--- | :--- | :--- | :--- |
| **🎨 見た目から** | 画面クリア & ステータスバー描画 | サンプル行の描画 & カーソル配置 | Raw Mode & キー取得 | 入力・編集ロジック接続 |
| **🎮 入力から** | Raw Mode & キーエコー | 終了キー & 矢印キー判定 | カーソル移動 & 画面再描画 | バッファ操作 & ファイル保存 |
| **📄 ロジックから** | `lines` への文字挿入・削除関数 | 行分割・改行処理 | Raw Mode & キー受け渡し | 画面描画との合流 |

## 🌐 発展：ブラウザ（WASM）や WASI でも動かす場合

ローカルターミナル以外のターゲット（`xterm.js` + WASM によるブラウザアプリや WASI ランタイム）にも対応させたい場合は、**コアをブロッキングループにせず「入力文字列を受け取って ANSI 文字列を返すイベント駆動ステートマシン」として分離**します（詳細とブラウザ特有の IME / SKK / macOS ショートカット / マウススクロール対策は [`docs/browser-wasm-runtime.md`](./browser-wasm-runtime.md) を参照）。

- **`render()` を純粋に保つコツ**: マウスホイール等で「カーソルは動かさず画面だけスクロール」したい場合、`render()` の先頭で無条件にスクロール追従（`ensure_cursor_visible()`）を呼ばず、キー入力やクリック時の更新処理側でのみ追従を呼ぶのがポイントです。

## 🧩 発展アーキテクチャの実装パターン

基本のエディタが完成したあと、実用的なエディタ機能へ伸ばす際の代表的な構造パターンです（実装レシピの詳細は [`docs/extension-ideas.md`](./extension-ideas.md) を参照）。

| 機能 | コア構造の拡張ポイント | 描画・入力での注意点 | 参照実装 |
| :--- | :--- | :--- | :--- |
| **マルチバッファ & タブ UI** | `Editor`（`buffers[]`, `activeBuf`）と `Buffer`（`lines`, `cursor`, `rowOffset`, `isModified`）の 2 層分離 | Row 1 にタブバーを置く場合、本文領域が Row 2 始まり（`textRows = rows - 3`）になり、クリック座標やカーソル Y 座標も +1 ずれる | [examples/go/](../examples/go/) |
| **範囲選択** | `anchor`（開始点）＋ `cursor`（現在点）を保持し、常に正規化した `(start, end)` で操作 | 選択中に文字入力すると「選択削除 → 挿入」で置換。SGR `?1002h` でマウスドラッグも扱える | [examples/moonbit/](../examples/moonbit/), [examples/zig/](../examples/zig/) |
| **Piece Table + マルチカーソル** | `Selection { anchor, head }[]` をオフセット昇順で持ち、後ろから編集を適用して 1 スナップショットで Undo/Redo | ハードウェアカーソルはプライマリ 1 箇所のみ、副カーソルは反転色（`\x1b[46;30m` 等）で描画 | [examples/zig/](../examples/zig/) |
